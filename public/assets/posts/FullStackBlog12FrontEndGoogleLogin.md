### Full Stack Personal Blog Development 12: Frontend Google Login Integration

> Google login functionality provides a convenient third-party authentication method for the blog application, allowing users to quickly log in using their Google account without registering a new account.

#### 1. Overview

**Core Features**:

- Google OAuth 2.0 authentication flow
- JWT Token acquisition and storage
- Automatic user information synchronization
- Login state persistence

**Technology Stack**:

- `@react-oauth/google`: Google OAuth React component library
- `@tanstack/react-query`: Data fetching and state management
- `js-cookie`: Cookie management
- Orval: Auto-generated type-safe API hooks

#### 2. Install Dependencies

Install Google OAuth React component library:

```bash
pnpm add @react-oauth/google
```

**Dependency Description**:

- `@react-oauth/google`: Provides `GoogleOAuthProvider` and `GoogleLogin` components
- Supports both popup and redirect login modes
- Automatically handles Google OAuth 2.0 authentication flow

#### 3. Configure Google OAuth Client ID

**3.1 Get Google OAuth Client ID**

1. Visit [Google Cloud Console](https://console.cloud.google.com/)
2. Create a new project or select an existing project
3. Enable Google+ API
4. Create OAuth 2.0 Client ID
5. Configure authorized redirect URI (e.g., `http://localhost:3000`)
6. Get Client ID

**3.2 Configure Environment Variables (Recommended)**

Create or update `.env.local` file in project root:

```env
NEXT_PUBLIC_GOOGLE_CLIENT_ID=your-google-client-id.apps.googleusercontent.com
```

**Note**: Use `NEXT_PUBLIC_` prefix to make variables accessible on the client side.

**3.3 Read Environment Variables (Recommended)**

Define constants in `src/lib/constants.ts`:

```typescript
export const GOOGLE_CLIENT_ID = process.env.NEXT_PUBLIC_GOOGLE_CLIENT_ID || ''
```

**Note**: In the current implementation, the Client ID is hardcoded in the component. Production environments should use environment variables for management.

#### 4. Implement Login Page Component

Implement the login page in `src/app/[locale]/login/page.tsx`:

**4.1 Import Necessary Dependencies**

```typescript
'use client'

import { GoogleOAuthProvider } from '@react-oauth/google'
import { GoogleLogin } from '@react-oauth/google'
import { usePostApiUsersGoogleLogin } from '@/lib/api/generated'
import { setAccessToken } from '@/lib/auth'
import { useLocale, useSearchParams } from 'next/navigation'
import { toast } from 'sonner'
// If using environment variables, import from constants
// import { GOOGLE_CLIENT_ID } from '@/lib/constants'
```

**4.2 Use Google Login Hook**

```typescript
export default function LoginPage() {
  const locale = useLocale()
  const searchParams = useSearchParams()
  const returnTo = searchParams.get('returnTo')

  const { mutate: googleLogin, isPending: isGoogleLoginPending } = usePostApiUsersGoogleLogin({
    mutation: {
      onSuccess: (response: any) => {
        toast.success('Login successful!')
        setAccessToken(response.token)
        window.location.href = returnTo ? decodeURIComponent(returnTo) : `/${locale}`
      },
      onError: (error: any) => {
        toast.error(error.message || 'Login failed, please try again')
      },
    },
  })
```

**Key Points**:

- `usePostApiUsersGoogleLogin`: Type-safe API hook automatically generated by Orval
- `onSuccess`: Save token and redirect after successful login
- `onError`: Handle login failure
- Supports `returnTo` parameter to redirect to specified page after login

**4.3 Render Google Login Component**

```typescript
return (
  <div className="flex h-[80vh] items-center justify-center px-4">
    <div className="flex w-full max-w-sm flex-col items-center justify-center space-y-6">
      <div className="space-y-2 text-center">
        <h2 className="text-3xl font-bold">Sign In</h2>
        <p className="text-muted-foreground">Please enter your account information</p>
      </div>

      <GoogleOAuthProvider clientId="your-google-client-id.apps.googleusercontent.com">
        <GoogleLogin
          ux_mode="popup"
          onSuccess={(credentialResponse: any) => {
            googleLogin({ data: { credential: credentialResponse.credential } })
          }}
          onError={() => {
            toast.error('Google login failed, please try again')
          }}
        />
      </GoogleOAuthProvider>
    </div>
  </div>
)
```

**Component Configuration Description**:

- `GoogleOAuthProvider`: Provides Google OAuth context, needs to wrap all components using Google login
- `GoogleLogin`: Google login button component
- `ux_mode="popup"`: Use popup window mode (alternative: `"redirect"` redirect mode)
- `onSuccess`: Login success callback, receives `credentialResponse.credential` (JWT Token)
- `onError`: Login failure callback

#### 5. Token Management

**5.1 Token Storage**

Implement token storage and reading in `src/lib/auth.ts`:

```typescript
import Cookies from 'js-cookie'

export function setAccessToken(token: string) {
  Cookies.set('access_token', token, {
    expires: 7, // 7 days expiration
    path: '/',
  })
}

export function getAccessToken() {
  return Cookies.get('access_token') || null
}

export function clearAuth() {
  Cookies.remove('access_token', { path: '/' })
}
```

**Storage Method Description**:

- Use `js-cookie` library to manage cookies
- Token stored in cookie named `access_token`
- Set 7 days expiration time
- Path set to `/` to make it accessible throughout the application

**5.2 Automatically Include Token in API Requests**

Automatically add token to request headers in `src/lib/apiFetch.ts`:

```typescript
import { getAccessToken } from './auth'

export async function apiFetch(url: string, options: RequestInit = {}) {
  const fullUrl = API_BASE_URL + url
  const token = getAccessToken()

  const headers = {
    ...(options.headers || {}),
    Authorization: token ? `Bearer ${token}` : '',
    'Content-Type': 'application/json',
  }

  const res = await fetch(fullUrl, { ...options, headers })
  // ... handle response
}
```

#### 6. User State Synchronization

**6.1 Get User Information on App Initialization**

Implement automatic user information fetching in `src/components/appInit/index.tsx`:

```typescript
'use client'
import { getAccessToken } from '@/lib/auth'
import { useUserStore } from '@/store/userStore'
import { useGetApiUsersMe } from '@/lib/api/generated'
import { useEffect } from 'react'

export default function AppInit() {
  const token = getAccessToken()

  const { data: user, isLoading } = useGetApiUsersMe({
    query: { enabled: !!token }, // Only request when token exists
  })

  useEffect(() => {
    if (user) {
      useUserStore.setState({ user }) // Update global user state
    }
  }, [user])

  return null
}
```

**Key Points**:

- `enabled: !!token`: Only make request when token exists, avoid unnecessary API calls
- Use Zustand for global state management of user information
- Import `AppInit` component in application root layout

**6.2 Import AppInit in Root Layout**

In `src/app/[locale]/layout.tsx`:

```typescript
import AppInit from '@/components/appInit'

export default async function LocaleLayout({ children, params }: Props) {
  return (
    <html>
      <body>
        <AppInit />
        {children}
      </body>
    </html>
  )
}
```

#### 7. Backend API Interface

Frontend calls backend `/api/users/google-login` API, passing the credential returned by Google:

**Request Format**:

```typescript
POST /api/users/google-login
Content-Type: application/json

{
  "credential": "eyJhbGciOiJSUzI1NiIsImtpZCI6Ij..."
}
```

**Response Format**:

```typescript
{
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "expiration": "2024-01-01T12:00:00Z"
}
```

The backend API will:

1. Validate Google JWT credential
2. Extract user information (email, name, etc.)
3. Create or find local user
4. Generate application JWT Token and return

#### 8. Development Steps Summary

1. **Install Dependencies**: Install `@react-oauth/google` library
2. **Configure Client ID**: Create OAuth client in Google Cloud Console, get Client ID
3. **Set Environment Variables**: Configure Client ID in environment variables
4. **Implement Login Component**: Use `GoogleOAuthProvider` and `GoogleLogin` in login page
5. **Call Backend API**: Use Orval-generated hook to call `/api/users/google-login`
6. **Handle Login Response**: Save token to cookie after successful login
7. **Implement Token Management**: Create `setAccessToken`, `getAccessToken`, `clearAuth` functions
8. **Automatically Include Token**: Automatically add Authorization header in `apiFetch`
9. **Synchronize User State**: Get user information on app initialization and update global state
10. **Handle Page Redirect**: Redirect to homepage or page specified by `returnTo` parameter after login

#### 9. Security Considerations

1. **Client ID Security**:
   - Use environment variables to store Client ID in production
   - Do not commit Client ID to public code repositories
   - Configure correct authorized redirect URI in Google Cloud Console

2. **Token Security**:
   - Token stored in cookie, set reasonable expiration time
   - Use HTTPS in production
   - Backend validates Google credential validity

3. **Error Handling**:
   - Properly handle login failure cases
   - Provide friendly error messages
   - Log errors for troubleshooting

4. **User Experience**:
   - Display login loading state
   - Support redirect to originally accessed page after login
   - Provide clear login guidance

#### 10. Common Issues

**Q: Token not saved after login?**

A: Check if `setAccessToken` function is called correctly and if cookie setting is successful.

**Q: API request returns 401 unauthorized?**

A: Confirm if token is correctly stored in cookie and if `apiFetch` correctly adds Authorization header.

**Q: Google login popup blocked?**

A: Ensure browser allows popups, or switch to `ux_mode="redirect"` redirect mode.

**Q: User information not automatically loaded?**

A: Check if `AppInit` component is correctly imported, if token exists, and if `useGetApiUsersMe`'s `enabled` condition is correct.
